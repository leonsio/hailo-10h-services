# Browser playground

Status, text/image chat and speech tests, request metrics and language controls. `app.js` loads UI catalogues from the API. `recorder-worklet.js` captures mono audio; microphone access requires browser-supported secure context.

The monitoring overview is available at `/monitor` and refreshes every five seconds. Its authenticated `/v1/monitor` endpoint includes `/health` status, startup phase/errors, one-hour per-service request counts and timings, application/host resources per gateway and worker PID, and up to 100 recent application log lines separately for each service process. Metrics are kept in memory for the current gateway process lifetime; old counts expire after one hour. CPU usage needs two refreshes. Detailed inference/request logs require `settings.debug_log`; request-payload events are excluded from the browser log buffer and the regular journal remains the complete log source.

The Playground, Monitoring and Settings pages share an API key in `sessionStorage` for the current browser tab. `settings.api_no_auth_networks` can allow selected HTTP/WebSocket socket peers to access the API without a key, independently from the MCP exemption.

The `/settings` page edits scalar YAML fields, validates the resulting configuration, and writes it atomically with a version check. API key and MQTT password values are never sent to the browser; leaving them blank retains their current values. Saving reformats YAML comments away. Request timeout, Piper input-character limit, HA waiting messages, YOLO confidence and maximum detections are applied to the running service immediately after a successful save. Model selection/enablement, native resources, listener addresses/ports, authentication/network exemptions, debug logging and other non-runtime fields require a restart and are labeled accordingly. The systemd deployment exposes restart actions from Settings and Monitoring. Writable configuration is stored in the service state directory and exposed at `/etc/hailo-10h-services.yaml`; environment overrides take precedence. The log view switches among Gateway/LLM/Hailo/Piper process tabs and offers combinable service, event, operation, protocol and model filters for tagged lines.

The overview shows enabled inference services. The system services panel shows hostname, HTTP/MCP binding and local socket IP/port, Wyoming binding/readiness, MQTT broker/connection and ZMQ endpoint/readiness. The separate Hailo-10H panel shows the installed HailoRT Python-package version plus NNC/CPU utilization, aggregate accelerator RAM, temperature and actual throttling state where those Control APIs are supported by the installed runtime/firmware. A collector in the Hailo worker publishes a cached snapshot every five seconds, independently from inference and the gateway event loop. Unsupported methods and `-1` error fields remain unavailable; unsupported operations are not retried on every refresh. Enabled protection is not interpreted as actual throttling. Resident models come from native objects successfully initialized by this service; HailoRT does not supply a global resident-model list or live RAM per model. The list is cleared when the worker stops.

All pages use the shared `common.js` / `common.css` header/footer navigation and interface localization. The interface-language selector is on `/settings`; it applies immediately and is persisted under `hailo-ui-language` in origin-local `localStorage`. Changes also update already open tabs, while unsaved YAML form inputs stay intact. The separate service-language YAML setting still needs a restart. Settings are grouped vertically by transport, model role and integration. Model fields use role-filtered catalogue choices from `/v1/settings`; configured local HEF selections remain available. The monitoring service cards include smaller model captions for successfully loaded models. Log views remember both scroll axes per process/service tab, including the desired horizontal offset when a shorter batch temporarily clamps it.
